# סקירת אבטחת מידע ותוכנית הקשחה — ethical-supplements.com

תאריך: 30.10.2026. היקף: האתר החדש (Astro על Vercel), ה-CMS (Sanity), הפונקציות
בצד השרת (טופס צור קשר, פיד אינסטגרם, הפניות), התלויות, והחשבונות שסביבם.

## 1. תמונת מצב: מה מגן על האתר כבר היום

- **אתר סטטי.** כמעט כל העמודים הם קבצי HTML מוכנים מראש. אין מסד נתונים, אין
  התחברות, אין עגלת קניות (החנות היא אתר נפרד). רוב סוגי הפריצה הקלאסיים
  (SQL injection, השתלטות על חשבונות, הרצת קוד בשרת דרך עמוד) פשוט לא קיימים כאן.
- **שלוש פונקציות שרת בלבד:** `/api/contact`, `/api/instagram`, ונתיב ההפניות.
  כולן קצרות, בלי גישה לנתונים רגישים, ועם סודות שמגיעים רק ממשתני הסביבה ב-Vercel.
- **סודות לא בקוד.** כל הטוקנים (אינסטגרם, מייל) יושבים ב-Vercel בלבד; הקוד ב-GitHub
  נקי מהם (נבדק: אין קבצי `.env` בקומיטים).
- **HTTPS בכל מקום** עם HSTS, תעודה אוטומטית של Vercel.
- **תוכן מה-CMS מוצג בצורה בטוחה:** טקסט מ-Sanity עובר Escape לפני הרינדור,
  קישורים חיצוניים נפתחים עם `rel="noopener"`, סרטוני יוטיוב דרך
  `youtube-nocookie`.
- **טופס צור קשר** עם מלכודת בוטים, הגבלת קצב, מגבלות אורך, ובלי אחסון של הפניות.
- **מכסת Sanity:** הבנייה קוראת דרך ה-CDN בלבד; הטוקנים לא בשימוש בייצור.

## 3. מה בוצע היום בקוד (כבר באוויר)

1. **כותרות אבטחה על הדומיין** (vercel.json): Content-Security-Policy שמגדירה בדיוק
   מאילו מקורות מותר לטעון סקריפטים, סגנונות, תמונות, מדיה, פריימים וחיבורים
   (Sanity, OpenStreetMap, אינסטגרם, יוטיוב, Google Fonts, Web3Forms, וספקי
   אנליטיקס מוכרים לעתיד: GTM/GA4, Meta Pixel, TikTok, Hotjar); `frame-ancestors
   'none'` + `X-Frame-Options: DENY` (אי אפשר להטמיע את האתר באתר אחר, מונע
   Clickjacking); `X-Content-Type-Options: nosniff`; `Referrer-Policy`;
   `Permissions-Policy` (מצלמה/מיקרופון/תשלום חסומים, מיקום רק לאתר עצמו);
   HSTS כולל תתי-דומיינים. נבדק מקומית על 12 עמודים: אפס הפרות CSP.
2. **Escape של JSON בתוך `<script>`** (JSON-LD, נתוני חנויות).
3. **סינון סכימת קישורים** בתוכן ה-CMS: רק http/https/mailto/tel/יחסי.
4. **`/api/contact`:** בדיקת Origin (רק הדומיין שלנו וכתובות Vercel), מגבלת 32KB
   לגוף הבקשה, הגבלת קצב 4 הודעות ל-10 דקות לכתובת, לוג לכל שליחה/חסימה.
5. **`/api/instagram`:** רק כתובות https מהפיד מגיעות לדפדפן.
6. **`/_image`** מופנה ל-404.
7. **נתיב ההפניות/404:** Cache בקצה (301 ליום, 404 ל-10 דקות).

## 4. מה דורש פעולה שלכם (חשבונות והגדרות)

**מיידי (היום):**
1. **לבטל את טוקן ה-Editor של Sanity** ששימש בעבודה: sanity.io/manage → הפרויקט →
   API → Tokens → למחוק. אם יידרש טוקן בעתיד, ליצור חדש ולהעביר רק דרך משתנה
   סביבה, לא בצ'אט. (אותו עיקרון לכל סוד.)
2. **אימות דו-שלבי (2FA)** על ארבעת החשבונות שמחזיקים את האתר: GitHub, Vercel,
   Sanity, Meta for Developers. בלי זה, סיסמה דלופה אחת = שליטה באתר.
3. **Vercel → Settings → Deployment Protection:** להפעיל "Vercel Authentication"
   לפריסות Preview (הפריוויו מציג טיוטות ורץ עם טוקן קריאה).

**השבוע:**
4. **Sanity → Members:** לוודא שרק אנשים פעילים חברים, ושעורכים הם Editor ולא
   Administrator. **Sanity → API → CORS origins:** רק category5.sanity.studio
   ו-localhost לפיתוח.
5. **Vercel → Environment Variables:** לוודא שהסודות (MS_*, INSTAGRAM_*, SMTP_*)
   מסומנים "Sensitive" ושאינם מוקצים לסביבות שלא צריכות אותם.
6. **דואר:** לבדוק ב-mxtoolbox.com שלדומיין ethical-supplements.com יש SPF, DKIM ו-DMARC
   (לפחות `p=quarantine`). זה מה שמונע ממישהו לשלוח מיילים שנראים כאילו הגיעו
   מכם, ומשפר את הגעת המיילים של הטופס.
7. **GitHub → Branch protection** על ענף הייצור: למנוע force-push ומחיקה.
8. **יומן רוטציה:** טוקן אינסטגרם (60 יום), סוד האפליקציה במטא (24 חודשים),
   טוקנים ב-Vercel. תזכורת ביומן.

**לשיקולכם:**
9. **Vercel WAF / Attack Challenge Mode:** זמין בלוח של Vercel; מסנן בוטים
   ותוקפי DDoS בלחיצה אחת ברגע שיש סימנים לתנועה חריגה.
10. **Cloudflare Turnstile** על טופס צור קשר אם יתחיל להגיע ספאם למרות ההגנות
    (אפשר להוסיף בחצי שעה, בלי CAPTCHA מעצבן למשתמש).

## 5. שלב 2 (אחרי אישור)

1. **שדרוג ל-Astro 5 + מתאם Vercel 8** (סוגר את כל התראות ה-npm הרלוונטיות).
   שינוי תשתיתי: אבצע בענף נפרד, Vercel יפיק לו פריסת Preview לבדיקה, ורק אחרי
   אישור ימוזג לייצור. כשעה-שעתיים עבודה + בדיקה.
2. **CSP הדוק יותר** בלי `'unsafe-inline'` לסקריפטים (דרך hash לכל סקריפט מוטמע).
   דורש גם שינוי באופן הזרקת קטעי המעקב מה-CMS. שיפור, לא קריטי.
3. **ניטור:** התראת מייל מ-Vercel על שגיאות בפונקציות, ובדיקת לוגים חודשית
   לחסימות של הטופס.

## 6. מה לא רלוונטי לאתר הזה (ולמה)

- **הזרקת SQL / השתלטות על משתמשים:** אין מסד נתונים ואין משתמשים באתר.
- **גניבת פרטי תשלום:** אין תשלום באתר; החנות היא מערכת נפרדת ושם האחריות
  שלה (מומלץ לוודא שגם לה יש HTTPS, 2FA ועדכונים).
- **הפניות פתוחות (Open Redirect):** נתיב ההפניות מפנה רק ליעדים מהרשימה הקבועה
  שלנו, לעולם לא לכתובת שהגיעה מהמשתמש.
